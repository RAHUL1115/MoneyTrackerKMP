# Code is packaged by feature, with each layout inside the feature

Kotlin code is grouped by feature (`home`, `activity`, `entry`, `accounts`, `insights`, `messages`, `settings`, `backup`, `webdashboard`, `lists`), not by layer. Each feature keeps its shared state holders at its root and each layout's screens in `classic/` and `fresh/` below it, so both layouts of one screen sit side by side with the logic they share. Pieces used everywhere live in `core`, `domain`, `data`, `designsystem` and `app`. The app stays one Gradle module: the split is for reading, and more modules would add build setup without a second app to share them. The `data` package keeps its name because SQLDelight generates `app.moneytracker.db` and a rename would gain nothing. Android components named in the manifest (the activity, application, receivers, widgets and the web dashboard service) stay where they are, because renaming them would remove widgets people have placed and reset their saved component state. The move was made as mechanical commits that change only files' places, package lines and imports; they are listed in `.git-blame-ignore-revs` so `git blame` skips them.
